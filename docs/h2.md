# Closed-loop H2 mimic and sim2sim

`Mjlab-Tracking-Flat-Unitree-H2` trains a Unitree H2 to imitate a 50 Hz reference
motion using MuJoCo Warp. It also supplies the MJWarp environment and policy
loader used by the Newton VBD sim2sim recorders and benchmarks.

The task adds an H2 robot configuration, motion validation, explicit head
rewards, and an optional actor-only checkpoint loader. It does not change mjlab's
simulation or environment managers. No robot assets, reference motions, policy
weights, experiment logs, or videos are distributed here.

## Configuration

| Setting | Value |
|---|---|
| Task | `Mjlab-Tracking-Flat-Unitree-H2` |
| Robot | `H2loop_complete.xml`; 37 joints, 31 actuated |
| Loop constraints | Six original XML tendon equalities; retain `solref` and `solimp` |
| Physics | 5 ms, `implicitfast`, Newton solver |
| Solver limits | 100 iterations, 50 line-search iterations, tolerance `1e-8` |
| Control | Decimation 4, 50 Hz |
| Limits | Release joint position and control-position limits; retain effort limits |
| Actuation | PD gains and action scales in `h2_constants.py`; passive damping 0.05 |
| Actor | 194 inputs, ELU MLP 512/256/128, 31 outputs; observation normalization |
| Rewards | Body tracking plus separate head joint, orientation, and position terms |
| Training | 8196 environments, PPO, 24 steps per rollout, 30000 iterations |
| Play | One environment by default, no observation noise or randomization events |

The actor interface is compatible with the supplied checkpoint. These settings
are not claimed to match Unitree's unpublished training or validation setup.
Training environment count (8196) is distinct from the benchmark counts
(1024, 4096, 8192).

## External inputs

Arrange separately supplied inputs relative to the mjlab checkout:

```text
h2_description/
  H2loop_complete.xml
  meshes/                    # Keep the filenames referenced by the XML.
sim2sim_inputs/
  h2_360dankou.npz
  model_29999.pt
```

These directories, generated outputs, and `*.pt` / `*.pth` are ignored by Git.
The XML is read without modifying it on disk. Resolve the model at load time
with `MJLAB_H2_XML`; if unset, use `h2_description/H2loop_complete.xml` relative
to the current working directory. Meshes are resolved relative to the XML.
Task discovery and configuration inspection do not require the assets.

```sh
export MJLAB_H2_XML=h2_description/H2loop_complete.xml
```

The reference NPZ must contain `fps=50`, joint position/velocity arrays of shape
`(T, 37)`, and body position, quaternion, linear velocity, and angular velocity
arrays of shape `(T, 38, 3/4)`. Quaternions use `wxyz`. Joint/body ordering must
match the supplied H2 model; array dimensions alone cannot verify ordering.

Known input SHA-256 checksums:

| Input | SHA-256 |
|---|---|
| `H2loop_complete.xml` | `5803ce64b4207867195128d5c94edb21c6265096c64475d7fc34a656e669e10e` |
| `h2_360dankou.npz` | `95370380434a609bb91e19617b6592051b3b8fea05ed947fb95446f6f6d2d52a` |
| `model_29999.pt` | `99534239b1b0eaeb8a99bd12db856aab831d236a89c61012724e6d2b76df18d2` |

Only load checkpoints from a trusted source: the actor loader uses PyTorch's
full checkpoint deserialization. The weights and motion are external inputs,
not downloaded automatically.

## Install, train, and play

Run from the mjlab checkout on a CUDA-capable Linux machine:

```sh
uv sync --locked --extra cu128
uv run --no-sync python -m mjlab.scripts.list_envs --keyword H2

uv run --no-sync train Mjlab-Tracking-Flat-Unitree-H2 \
  --env.scene.num-envs 8196 \
  --env.commands.motion.motion-file sim2sim_inputs/h2_360dankou.npz \
  --agent.max-iterations 30000

uv run --no-sync play Mjlab-Tracking-Flat-Unitree-H2 \
  --checkpoint-file sim2sim_inputs/model_29999.pt \
  --motion-file sim2sim_inputs/h2_360dankou.npz \
  --num-envs 1 --device cuda:0 --viewer viser
```

Training starts fresh by default and writes TensorBoard logs and checkpoints
under `logs/rsl_rl/h2_closeloop_mimic/`. To warm-start only the actor, append
`--agent.actor-checkpoint sim2sim_inputs/model_29999.pt` to the training command.
This does not restore the critic, optimizer, or training iteration. Full training
resume remains the standard mjlab `--agent.resume` workflow.

## Newton VBD sim2sim and benchmarks

Use the [Newton H2 package and instructions][sim2sim], which also contain
[throughput results and commands][benchmark] and [loop-error measurements][closure].
Both simulators run the policy in feedback from their own state; this is not
action replay. The comparison uses 5 ms physics, decimation 4, and eight VBD
iterations. Benchmark FPS counts environment control frames per second.

Use sibling checkouts named `mjlab` and `newton_f`. Prepare the external inputs
in the locations required by each checkout. In an isolated benchmark environment,
install the Newton dependencies and the recorded Warp version; do not change an
active training environment:

```sh
# Run from mjlab after the installation above.
uv pip install --python .venv/bin/python --index https://pypi.nvidia.com/ \
  warp-lang==1.16.0.dev20260716
uv pip install --python .venv/bin/python --no-deps -e ../newton_f

cd ../newton_f
H2_PYTHON=../mjlab/.venv/bin/python
export MJLAB_H2_XML=h2_description/H2loop_complete.xml

uv run --no-project --python "$H2_PYTHON" python -m h2_sim2sim.record_mjlab \
  --checkpoint sim2sim_inputs/model_29999.pt \
  --motion sim2sim_inputs/h2_360dankou.npz \
  --steps 476 --output sim2sim_out/mjlab.npz

for h2_envs in 1024 4096 8192; do
  uv run --no-project --python "$H2_PYTHON" python -m h2_sim2sim.benchmark mjlab \
    --num-envs "$h2_envs" \
    --checkpoint sim2sim_inputs/model_29999.pt \
    --motion sim2sim_inputs/h2_360dankou.npz \
    --warmup 40 --steps 400 --repeats 3 \
    --output "sim2sim_out/benchmark/mjlab_${h2_envs}.json"
done
```

Run the VBD recorder, overlay renderer, VBD benchmarks, and closure comparison
using the linked instructions in the same environment. Output filenames must be
new. Keep MuJoCo and MuJoCo Warp at 3.11.0, Torch at 2.9.0+cu128, and NumPy at
2.5.1 for the recorded benchmark configuration (Python 3.13). The training
lockfile selects Warp 1.14.0; the benchmark explicitly overrides it. Use
`--no-sync` / `--no-project` after this override to avoid replacing it.
GPU model and runtime versions affect FPS; a rerun is not expected to reproduce
the exact published throughput on different hardware.

## Checks

CPU checks do not require an NVIDIA GPU. From the mjlab checkout:

```sh
uv sync --locked --extra cpu --group dev
uv run --no-sync pytest tests/test_h2_tracking.py
make check
```

The suite checks external asset loading, joint/actuator order, preserved tendon
parameters, position/effort limits, motion validation, and head rewards.
Three model checks skip when external H2 assets are absent; set `MJLAB_H2_XML`
to run them. These checks are not GPU training or throughput validation.
